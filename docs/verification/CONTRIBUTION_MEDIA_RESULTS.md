## Recorder feedback and immediate playback (2026-10-18)

Recording uses the browser's MediaRecorder and native audio player, with no additional dependency. Permission opening has its own cancellable state; the prominent recording panel appears when capture starts, with a pulsing indicator, elapsed clock, native duration progress and a Stop recording button. Reduced motion disables pulse/spinner animation. The microphone is released after Stop, errors, cancellation and navigation; late permission results are released rather than starting abandoned captures.

Previously, a stopped clip waited for private upload, server validation and a fresh download before playback. A memory-only object URL now provides immediate local playback while the reserve/upload/check/refresh stages finish. Successful recordings keep the same local player mounted, avoiding another download or an interruption when saving finishes. Failed recordings remain locally playable and retryable; their own incomplete reservation is discarded when possible. A failed clip must be saved or discarded before the letter can be sent. URLs are revoked on replacement/discard/unmount, without persistent private caches. Existing server-backed audio requests metadata earlier, while private authorization remains unchanged.

Automated verification: 147 tests in 15 files, including slow uploads, retrying the same clip, permission denial/cancellation, elapsed time, the automatic duration stop, capture errors, cleanup and local-source reuse. Desktop and 390px phone layout checks used an isolated synthetic state preview, removed before production build; no real microphone permissions or recordings were used. Physical microphone/browser capture still needs a device playtest. No database migration is required.

Native API reference: https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder
